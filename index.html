📊 Y9–Y13 scaffolding guide — what each year group is expected to achieve
Y9 · Age 13–14
Find bugs 1–6 with Copilot Chat help
Use comments to drive Copilot
Build a working feature with HTML + basic JS
Stretch: add CSS styling and a progress bar
Y10 · Age 14–15
Find all 10 bugs independently
Write specific, effective prompts
Build a feature with input validation
Stretch: add event listeners and DOM manipulation
Y11 · Age 15–16
Find bugs AND explain why each is wrong
Critique Copilot output before accepting
Build feature + write their own unit logic
Stretch: multiple features, error handling
Y12 · Age 16–17
Debug AND fix the logical/stretch bugs
Prompt engineer for quality over speed
Build with localStorage persistence
Stretch: multiple goals, simulated transfers
Y13 · Age 17–18
Find bugs, fix, and refactor the function
Use Copilot to review its own output
Build full feature with API or localStorage
Stretch: loan calculator, fraud simulator, date logic
Key pairing strategy
Mix year groups within pairs where possible. Y13 explaining a concept to Y9 reinforces their own understanding — and Copilot Chat's plain-English explanations act as a natural scaffold for younger participants who don't need to ask you.

Y9–Y13 differentiation in this block
All three rounds work across the full age range — Y9s compete on speed (Round 1), Y13s are pushed on quality (Round 2) and explanation (Round 3). The Bug Blitz answer echoes Bug 9 from the dashboard, which Y11+ will recognise. The golden rules serve as an explicit scaffold for Y9–Y10 going into the build phase.

The key gap for Y9
The jump from Level Up → blank page → build a feature can cause paralysis for Y9 participants. The Build Starter Template (coming next) closes this — it gives them a structured HTML file with guided comments so Copilot knows what to fill in. Y11+ don't get it; they start from scratch. That's the one thing currently missing from the pack.
