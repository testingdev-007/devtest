1:00–1:03 The Reveal 3 min

They've just spent 30 minutes using Copilot without necessarily knowing what it is. Open with the mind-blowing version of the truth.

Say this
"You just used GitHub Copilot to debug a real banking app. Here's what was actually happening. Copilot was trained on billions of lines of public code — essentially, it has read more code than any human ever could. When you asked it about a bug, it wasn't looking it up. It was pattern-matching against everything it has ever seen. And it still got some things wrong. That's important."

Then hit them with the fast facts — put Slide 1 on screen from level-up-screen.html:

100M+
developers have code on GitHub
1B+
lines of code Copilot was trained on
Right now
your Codespace is a real Linux computer running in a Microsoft data centre
Still wrong
Copilot confidently produces incorrect code around 30% of the time
Energy note
Keep this punchy. Read the facts fast. The point is to make them feel like they've been doing something real — because they have.
1:03–1:08 GitHub & Codespaces in 5 Minutes 5 min

Three concepts, fast. Do this live on your screen — don't use slides, just show the real thing.

1
GitHub = your project folder + a time machine ~90 sec

Go to the repo page on GitHub. Click the commit history. Show one commit.

Say
"Every time someone saves a meaningful change, GitHub records it. That's a commit. You can go back to any point in history. Professional developers use this constantly — it means you can never permanently break anything."
2
Codespaces = a real computer in the cloud ~90 sec

Ask someone: "Is VS Code running on your laptop right now?" Wait for the answer. Then:

Say
"It's not. It's running on a server in a Microsoft data centre somewhere in Europe. You're controlling it through your browser. The code you wrote is sitting on a computer you've never seen. That's a Codespace."
3
Copilot = autocomplete that read the internet ~1 min

Open a blank file. Type a comment. Watch Copilot suggest. Press Tab.

Say
"This is the bit we're going to practise now. Writing good comments is how you drive Copilot. The better you describe what you want, the better the code you get back. That's what the next 15 minutes is about."
1:08–1:25 Three Challenge Rounds 15 min

Three rounds, 5 minutes each. Pairs compete. You keep the energy up. Use the level-up-screen.html slide deck — it has built-in countdown timers. Click to advance between rounds.

Setup
Tell everyone to open a new file in their Codespace: File → New File → save it as challenge.js. That's where they'll write their challenge code.
1:08–1:13 Round 1 — Comment Race 5 min
Say this to intro the round
"Round one. I'm going to put a comment on screen. Your job is to type it into your file and use Copilot's inline suggestion to complete the code. First pair with a working function wins. You've got 3 minutes on the clock."

Put this on screen (Slide 3 in the deck):

// function that converts an amount in pounds to euros
// use a rate of 1.17, rounded to 2 decimal places

What to look for:

  • Participants type the comment into challenge.js
  • Copilot should suggest the function body — they press Tab to accept
  • Add console.log(convertToEuros(100)); underneath, save
  • Open a terminal (Ctrl+`) → run node challenge.js → the actual result prints
  • First working, proven result = winner
Why the console.log step matters
A function sitting in a blank JS file with nothing calling it is invisible — Copilot writes it, but nobody sees it actually work. Running it via Node makes the round genuinely testable rather than theoretical.
If Copilot doesn't suggest automatically
Tell them to press Alt+\ (Windows) or Option+\ (Mac) to trigger a suggestion manually.
After the round — say this
"Notice what just happened. You didn't write a single line of code. You described what you wanted, and Copilot wrote it. That's the skill — describing it precisely. Vague comment, vague code."
1:13–1:18 Round 2 — Best Prompt 5 min
Say this
"Round two. This time there's no winner by speed — there's a winner by quality. You've got one message in Copilot Chat. Just one. Use it to get Copilot to write a function that takes a name and a balance, and returns a personalised greeting. You've got 3 minutes. Go."

Put this on screen (Slide 5):

One Copilot Chat message. Get it to write a function that:
  → takes a person's name and their account balance
  → returns a greeting like: "Hi Sarah! Your balance is £250.00"
  → formats the balance with a £ sign and 2 decimal places

Best result wins. You get ONE message.

After 3 minutes: tell them to add console.log(theirFunctionName("Sarah", 250)); underneath, save, and run node challenge.js in the terminal to see the real greeting print. Ask 3–4 pairs to read their Copilot message out loud, then show the actual printed result. Group votes on the best one.

After the round
"The difference between a great result and a mediocre one came down to how specific the prompt was. The more constraints you gave — the format, the £ sign, the decimal places — the better the code. This is called prompt engineering and it's a real skill that real developers use every day."
1:18–1:25 Round 3 — Bug Blitz 7 min
Say this
"Final round. Copilot wrote this function. It looks right. It might be right. Your job is to find out — using Copilot itself. Paste the code into your file and ask Copilot Chat to review it. First pair to correctly identify the bug wins."

Put this on screen (Slide 7) — participants paste it into challenge.js:

function calculateMonthlyPayment(principal, annualRate, years) {
  const monthlyRate = annualRate / 12;
  const months = years * 12;
  const payment = principal * monthlyRate * Math.pow(1 + monthlyRate, months)
                / (Math.pow(1 + monthlyRate, months) - 1);
  return payment.toFixed(2);
}

The bug: annualRate / 12 should be annualRate / 100 / 12. The rate is passed as a percentage (e.g. 5 for 5%) but treated as a decimal. It's the same category as Bug 9 from the dashboard.

Good Copilot Chat prompt to suggest if they're stuck:

"Can you review this function for bugs? 
Pay attention to how the interest rate is being used."
Make the bug visible, not just readable
Add console.log(calculateMonthlyPayment(1000, 5, 1)); underneath, save, run node challenge.js. A real 5% loan wouldn't cost that much a month — seeing the actual wrong number is far more convincing than reading the code and taking someone's word for it.
Why this round matters
This demonstrates that Copilot can review its own (or anyone else's) code. That's genuinely useful. It also reinforces Bug 9 from the dashboard exercise — same class of error. Watch for the "oh, that's the same thing!" moment.
If Copilot refuses, flags "SQL injection," or otherwise acts oddly
This can happen if the code is asked about directly in the chat box without actually being saved in challenge.js first — Copilot's safety heuristics occasionally over-trigger on financial-sounding code (payment, principal, rate) with no real file behind it. The fix is exactly what the instructions say: make sure the function is genuinely pasted and saved in challenge.js before asking Chat to review it, not just typed into the chat message itself.
After the round
"Copilot wrote that bug. Then Copilot found it. That's not a contradiction — it's actually how the tool is most useful. Write fast, then review carefully. Use it in both directions."
1:25–1:28 The Three Golden Rules 3 min

Put Slide 9 on screen. Read them out. Keep it quick.

1
Be specific. The quality of the code Copilot gives you is directly proportional to how clearly you describe what you want. Vague in, vague out.
2
Always test it. Copilot is confident and wrong surprisingly often. Every function it writes, you run it. You check the result. You own the code.
3
Ask it to explain. If Copilot writes something you don't understand, ask it to explain. You can't fix code you don't understand. Never ship code you can't explain.
