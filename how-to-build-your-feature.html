How to Build Your Feature
A complete click-by-click build of a Savings Goal Tracker — from an empty starter file to a fully working feature. Same method works for any idea.
Building your own idea instead? Use exactly this same method — comment, Tab, save, test, repeat. Just swap the comments below for ones that describe YOUR inputs and outputs instead of a savings goal.
Before You Start

Step 1 of 7
Style the progress bar
1
Find TODO 1 in the CSS

Scroll down in the code until you find the comment that says TODO 1: Style the progress bar. Click right underneath it, on the empty line.

Type this comment
/* progress bar container and fill styles */

Wait a second — grey ghost text should appear underneath, suggesting CSS code. Press Tab to accept it.

What you should see
A block of new CSS code appears, styling something called .progress-track and .progress-fill. Save with Ctrl+S.
Nothing visible changes yet — that's normal
You've only written the styling rules. Nothing on the page uses them yet because you haven't added the HTML that needs them. That's the next step.

Now Things Get Visible
Step 3 of 7 — Add the progress bar HTML
3
Scroll down to the HTML section, find TODO 3

This one's in the HTML part of the file, below the input card.

Type this comment
<!-- savings goal progress card with a labelled progress bar and percentage -->

Press Tab. Save with Ctrl+S.

What you should see
Switch to your Live Server tab and refresh (it should update automatically, but refresh manually if not). A new card should now be visible on the page — a progress bar, even if it's showing 0% right now.
If you DON'T see it
Check the editor tab for a red squiggly line anywhere — that means a typo broke the HTML. Also confirm you saved (the tab title has a dot on it if unsaved). If it still doesn't show, ask Nova: "I added a progress card but it's not showing on the page — here's my code, what's wrong?"

4

A second new card appears below the progress bar in your preview — this is where the "amount left" message will eventually show.
✓ Milestone check: your page now has a heading, inputs, a button, a progress bar, and a result area. All the pieces are visible — none of them work yet. That's exactly on track.

The Big Moment
Step 7 of 7 — Wire it all together
7
Find the empty updateGoal() function

This is the function that runs when someone clicks the button. It's already started for you — you'll see:

function updateGoal() {
  // YOUR CODE GOES HERE
}

Click on that comment line and replace it with this comment, then press Tab:

Type this comment
// read goalName, targetAmount and savedAmount // from the inputs, validate them, calculate // progress, and update the display

Copilot should generate several lines that read your three input boxes and call the two functions you already built. Save with Ctrl+S.

✓
Test the whole thing for real

Switch to your Live Server preview tab. Fill in the three boxes with real numbers:

Goal name: "New trainers" Target: 80 Saved so far: 50

Click Update my goal.

What you should see
The progress bar should animate and fill to roughly 62%. The result card should show something like "£30.00 left to save."
If nothing happens when you click the button
Press F12, click Console, click the button again — look for red text. Copy it and ask Nova: "I clicked my button and got this error: [paste it]. What's wrong?"
🎉 If the bar filled in and the message appeared — your feature works. That's genuinely the hardest part done.
Now Break It On Purpose
Check it properly before you demo it
Try each of these. For each one, decide: is this OK, or does it need fixing?

Leave all three boxes empty and click the button. Does it show something sensible, or does it break?

Type a savings amount bigger than the target. Does the bar go past 100%, or does it cap sensibly?

Type a negative number. Does anything stop you, or does it just show something nonsensical?

Log whatever you find in your Feature Test Plan. If something breaks that shouldn't, that's your next thing to fix — ask Nova: "How do I stop someone entering a negative number here?"

Iterating
How to change something once it's built

Want to change how it looks? Find the relevant CSS rule (search for the class name, e.g. .progress-fill), change the value (a colour, a size), save, and check the preview.

Want to change how it behaves? Find the relevant function in the JavaScript, describe your change as a new comment right above the line you want different, and let Copilot suggest an update — or ask Nova directly: "How do I make X happen instead of Y?"

Got a wall of red errors? Don't panic — read only the first one, it's usually the real problem. Fix that, save, and see if the others disappear on their own.

🚀 The method never changes
Comment → Tab → Save → Test → Ask Nova if stuck → Repeat. Whatever you're building next — this feature's stretch goals, or a completely different idea — this is the whole loop.
